# MCP capability map

What the Cavalry MCP can do **today**, verified against the installed extension
(`com.canva.cavalry.mcp` 1.0.0) and Cavalry 2.8.0, not against README claims. The
machine-readable catalogue is [mcp-capability-map.json](mcp-capability-map.json),
regenerated by `scripts/build-capability-map.ts` — never hand-maintained.

## Architecture

```
MCP host  <--stdio-->  node bridge (server/index.js)  <--SSE-->  Cavalry app (localhost:6768)
```

The bridge forwards tool calls; it implements no scene logic. The real server lives inside
Cavalry (`libExtensionLayer.dylib`). Each host gets a per-host fingerprint and must be
approved once in Cavalry's dialog.

## The tools that exist

`read_preamble`, `execute_script`, `preflight_script`, `preflight_shader`,
`cleanup_workspace`, `list_library_scripts`, `read_library_script`,
`save_script_to_library`, `search_api`, `get_api_function`, `search_docs`, `read_doc`,
`search_layer_types`, `get_layer_definition`, `search_examples`, `read_example`,
`snapshot_layer`.

- `execute_script` refuses to run until `read_preamble` has been called in the session. It
  is marked destructive and is never auto-retried.
- `snapshot_layer` returns a PNG image block. Layer mode frames one layer tightly; comp
  mode (no `layerId`) renders the whole active comp; `frame` picks a moment and restores
  the playhead; `maxSize` is 32–1024.
- `preflight_script` checks **syntax only** — it does not validate the API surface or
  confirm a connection will land. Read a pass as "it parses".

## What the MCP does NOT provide

These are the gaps the skill works around with scripts and discipline, and the extension
plan proposes to close. See `integrations/cavalry-mcp/CAPABILITY-GAP.md`.

| Capability | State today | Workaround in-skill |
|---|---|---|
| Verified attribute mutation | none | the eight-step protocol: set, then `api.get` readback and compare |
| Connection verification | none | `api.getInConnectedAttributes`, plus visual confirmation |
| Keyframe inspection | none | `api.getKeyframeTimes` in a script |
| Symbolic ids across calls | none | keep the ids `api.create` returns; re-find by scene walk |
| Rollback | none; a failed/repeated run is not undone | capture a rollback point, delete leftovers before rebuild |
| Scene-graph export | none | walk `getChildren` / `getAllSceneLayers` in a script |
| Contact-sheet render | none | multiple `snapshot_layer` calls at chosen frames |
| Idempotent upsert | none | INSPECT and reuse the existing system; do not rebuild |
| Managed metadata | none | — |
| Before/after diffs | none | snapshot before and after |

## Raw script execution is off by default

`execute_script` is the one destructive tool. The skill's policy is: do not run raw script
until INSPECT, PLAN, and DISCOVER are done and a rollback point is recorded. Prefer the
discovery tools (`search_*`, `get_layer_definition`, `snapshot_layer`) for everything they
can answer, and `preflight_script` before any non-trivial `execute_script`.

## Capability-map entry shape

Each entry in the JSON catalogue carries: `namespace`, `method`, `signature`, `category`,
`returnType`, `mutatesScene`, `securityLevel`, `mcpCoverage`, `versionVerified`,
`testCoverage`, `limitations`, `sourceUrl`. Regenerate and validate:

```bash
node scripts/build-capability-map.ts --out references/mcp-capability-map.json
node scripts/validate-capabilities.ts references/mcp-capability-map.json
```
